# MASTER DEVELOPMENT PROMPT — KISS & RUN MOBILE GAME

You are an expert mobile game developer, game designer, UI/UX designer, and Android build engineer.

Build a complete, polished, production-ready mobile game called **"Kiss & Run"**.

The game should be a funny, chaotic, cartoon-style mobile game based on a very simple gameplay loop:

**APPROACH → CHOOSE CHARACTER → KISS → REACTION → CONSEQUENCE → RUN/ESCAPE → SCORE → NEXT ENCOUNTER**

The game must be easy to understand within 5 seconds, funny, highly replayable, and suitable for publishing on Google Play.

---

# 1. CORE GAME CONCEPT

The player controls a funny fictional adult character walking/running through different environments.

The player encounters other fictional adult characters.

The player can approach a character and tap a **KISS** button.

After the kiss, the NPC reacts randomly according to its personality.

The reaction must have a real gameplay consequence.

The player then has to deal with that consequence.

Examples:

* NPC loves the kiss → gives reward / follows player / speed boost
* NPC gets angry → chases player
* NPC slaps player → health decreases
* NPC calls police → police chase begins
* NPC laughs → nearby NPCs become distracted
* NPC screams → crowd gathers
* NPC calls friends → multiple NPCs chase player
* NPC kisses back → temporary speed boost
* NPC throws an object → obstacle appears
* NPC runs away → player can chase them for bonus points
* NPC gives coins → player collects reward
* NPC is secretly dangerous → unexpected trap

The game should be humorous and exaggerated rather than realistic.

All characters must clearly be fictional adults.

Do NOT include explicit sexual content, nudity, sexual acts, or minors.

The kiss should be represented as a short, harmless cartoon interaction.

---

# 2. IMPORTANT GAME DESIGN PRINCIPLE

The most important mechanic is:

## EVERY REACTION MUST HAVE A CONSEQUENCE.

Do not make reactions cosmetic only.

For example:

Kiss → Girl laughs → nearby people notice → crowd gathers → player gets surrounded → player must escape.

Another:

Kiss → Guy becomes angry → starts chasing → knocks over a street vendor → vendor chases player → dog gets involved → dog chases player.

Another:

Kiss → NPC loves it → gives player a heart → temporary speed boost.

Create a system where reactions can trigger secondary events.

---

# 3. CHAIN REACTION SYSTEM

Implement a chain-reaction system.

Example:

Player kisses NPC #1.

NPC #1 becomes angry.

NPC #1 starts chasing the player.

While chasing, NPC #1 collides with NPC #2.

NPC #2 becomes angry.

NPC #2 calls security.

Security begins chasing the player.

Security collides with a food cart.

Food cart falls over.

Food spills onto the road.

Player slips.

The player loses speed.

The original NPC catches up.

This should feel chaotic and funny.

Not every encounter needs a chain reaction, but the system must support them.

Use a probability-based event system.

# 46. MOST IMPORTANT DESIGN GOAL

The player should constantly think:

> "What is going to happen if I kiss this person?"

That uncertainty is the core of the game.

The game should reward experimentation.

A player should be able to replay the same environment multiple times and experience different outcomes because of randomized NPC personalities and reaction chains.

The game should be:

**Simple to play.**

**Funny to watch.**

**Chaotic to master.**

**Easy to replay.**

**Easy to expand with new reactions.**

Start by inspecting the current workspace/project.

Then implement the game incrementally.

Do not ask unnecessary questions. Make sensible technical decisions and continue building.

After implementation, run the project, test it, fix errors, and leave the workspace in a buildable state.
